# intervalClaude v0.3 — 动态错峰激活调度 设计

**日期**: 2026-05-24
**状态**: 已确认
**前置版本**: v0.2（OAuth + Keychain + use + tui 已就绪）

---

## 背景

v0.2 的 `start` 命令用"i × (300/N)"固定时间表预排错峰，但实际使用中暴露问题：
1. **没有自动切换** — 主帐号用满需手动 `use`
2. **静态时间表不反应实时 usage** — 用户用得快/慢都按固定时间
3. **死板** — 不能根据帐号实时状态（usage / 重置时间 / 套餐档次）动态决策

v0.3 改造为**反应式调度系统**：daemon 每周期评估"目标状态"vs"实际状态"，决定动作。

## 目标

- 真正的窗口重叠覆盖（N 个 5h 窗口错开 300/N 分钟）
- 主帐号用满或窗口过期 → 自动切换到健康度最高的备用
- 进度信号 + 时间信号 双触发预 ping（不依赖单一条件）
- 套餐差异化（Max 5x = Pro × 5，Max 20x = Pro × 20）
- TUI 完整可视化调度决策

## 核心算法

### 1. 健康度公式

```
health(account) =
    if window_not_started:
        weight × 1.0 × 300                 # 满血新人，按潜在 5h 算
    elif exhausted (usage ≥ 1.0):
        0
    elif window_expired:
        weight × 1.0 × 300                 # 已过期视为未激活
    elif window_remaining < 3min:
        0                                   # 即将过期，切过去不值得
    else:
        weight × (1 - usage) × window_remaining_min
```

**sub 权重**（可在 config 覆盖）：
```
pro      = 1
max_5x   = 5
max_20x  = 20
team     = 10
_default = 1   # 未知 sub
```

### 2. 切换触发条件

主帐号满足任一即切：

```
- usage ≥ 1.0           # 用满
- window_expired         # 窗口已过期
- ping 返回 limit_reached  # 最近一次 ping 失败标志
- active is null         # 没有活跃帐号（初始状态）
```

### 3. 预 ping 错峰算法

每周期，daemon 决定是否给一个"未激活"的备用帐号 ping。

```python
function should_pre_ping(accounts, active, now):
    N = total accounts
    if N <= 1: return null

    stagger_min = 300 / N

    # 候选 = 未激活的帐号，按健康度排序
    dormant = [a for a in accounts
               if a != active and a.window_not_started]
    if dormant is empty: return null
    dormant.sort(by=health, descending)

    # 已经在跑的备用数（不含活跃）
    running_backups = count(a for a in accounts
                            if a != active and a.window_running)

    # 下一个该 ping 的位置 = 当前已有备用 + 1
    next_index = running_backups  # 0-based

    if next_index >= len(dormant):
        return null  # 没有更多可 ping 的

    target_time_min   = (next_index + 1) × stagger_min
    target_usage_frac = (next_index + 1) / N

    elapsed_min = (now - active.window_start) / 60_000
    current_usage = active.usage

    if elapsed_min >= target_time_min or current_usage >= target_usage_frac:
        return dormant[0]   # 健康度最高的未激活

    return null
```

**特殊情况**：冷启动时 active 为 null。先选健康度最高的帐号 `ping + use`，下一周期再开始错峰。

### 4. 完整调度循环

```python
function schedule(accounts, active, now):
    # === Step 1: 决定切换 ===
    if needs_switch(active):
        candidate = best_switch_candidate(accounts, exclude=active)
        if candidate is null:
            log("all accounts exhausted — wait for reset")
            return ACTION_NONE
        if candidate.window_not_started:
            return [PING(candidate), USE(candidate)]
        return [USE(candidate)]

    # === Step 2: 决定预 ping（错峰建池）===
    next_ping = should_pre_ping(accounts, active, now)
    if next_ping:
        return [PING(next_ping)]

    return ACTION_NONE


function needs_switch(active):
    if active is null: return true
    if active.usage >= 1.0: return true
    if active.window_expired: return true
    if active.limit_reached_recently: return true
    return false


function best_switch_candidate(accounts, exclude):
    candidates = [a for a in accounts
                  if a.name != exclude.name and health(a) > 0]
    if candidates is empty: return null
    return max(candidates, by=health)
```

## 数据模型变更

### config.json 增加 scheduler 块

```json
{
  "interval_minutes": 100,
  "ping_prompt": "hi",
  "scheduler": {
    "enabled": true,
    "stagger_min": 75,
    "sub_weights": {
      "pro": 1,
      "max_5x": 5,
      "max_20x": 20,
      "team": 10,
      "_default": 1
    },
    "expire_threshold_min": 3,
    "auto_switch": true,
    "notify": true
  },
  "accounts": [...]
}
```

字段说明：

| 字段 | 默认值 | 含义 |
|------|--------|------|
| `enabled` | true | 总开关 |
| `stagger_min` | null (= 300/N 自动) | 错峰间隔分钟，null 时按帐号数自动算 |
| `sub_weights` | 见上 | 套餐权重映射 |
| `expire_threshold_min` | 3 | 窗口剩余少于此值视为 health=0 |
| `auto_switch` | true | 主帐号无效时是否自动 use |
| `notify` | true | 切换发生时是否发系统通知 |

### state.json 不变

不需要新增字段，调度信息按需从 config + Keychain 实时计算。

但**新增运行时字段**（仅内存，不持久化）：
- `account.limit_reached_at` — ping 返回 limit 时记录时间戳，10 分钟内有效

## 通知方式

**macOS 系统通知**（`osascript`）：

```bash
osascript -e 'display notification "MESSAGE" with title "intervalClaude" subtitle "SUBTITLE" sound name "Submarine"'
```

触发场景：

| 事件 | 标题 | 副标题 | 消息 |
|------|------|--------|------|
| 自动切换 | intervalClaude | 已切换帐号 | 主帐号已用完 → 备用1 |
| 全满 | intervalClaude | ⚠️ 所有帐号耗尽 | 最早重置: 备用1 (1h23m 后) |
| 预 ping 完成 | intervalClaude | 备用已就绪 | 已预 ping 备用2（窗口启动） |

**日志**：所有调度决策写入 `~/.intervalClaude/daemon.log`：

```
[2026-05-24T09:00:00] schedule: cold start, pinging 主帐号 (Max, health=1500)
[2026-05-24T09:00:01] schedule: USE 主帐号 OK
[2026-05-24T10:15:30] schedule: pre-ping 备用1 (health=300, target_time reached)
[2026-05-24T14:00:00] schedule: 主帐号 expired → SWITCH to 备用1
```

`interval-claude list` 增加 `--log` 参数查看最近 50 行调度日志。

## 风险与开放问题

### Q1 — Limit reached 的检测

ping 返回错误时，stderr 含 `"You've hit your limit · resets ..."`。Pinger 需要解析这个字符串，标记 `account.limit_reached_at = now`。

新增到 `src/pinger.js` 返回结果中：`result.limitReached: true`。

### Q2 — Daemon 切换 user 时的并发

如果 daemon 在切换 Keychain 时，用户同时手动 `use` 别的帐号，可能竞争。
处理：daemon 操作有锁文件 `~/.intervalClaude/.scheduler.lock`，手动 use 时检查锁状态。

### Q3 — 用户离开期间持续浪费

接受。这是错峰系统的固有代价（用户已确认选 A）。

### Q4 — sub_weights 未知值

代码先按字段值精确匹配，找不到走 `_default`。日志记录 "unknown sub: max_xxx"，用户可在 config 添加。
