# intervalClaude v0.2 — OAuth 多帐号 + Usage API + Use 命令 设计

**日期**: 2026-05-23
**状态**: 草稿
**前置版本**: v0.1 (已实现)

---

## 背景

v0.1 用 `claude setup-token` 生成的长效 token，问题：
1. 长效 token 没有 `user:profile` scope，**无法调 `/api/oauth/usage` 查剩余使用量**
2. 添加帐号流程繁琐：`/logout` → `/login` → `setup-token` → 复制 → `add` → 粘贴
3. 无法获知订阅类型 (Pro / Max5x / Max20x)

cc-switch 已验证：**直接读 macOS Keychain 里 claude CLI 的现有 OAuth token**（含完整 scopes），调 `/api/oauth/usage` 即可获取实时 usage。

## 目标

- 改造为 OAuth credential 备份/恢复模式
- 拿到真实 usage + 重置时间 + 订阅类型
- 新增 `use` 命令做全局帐号切换
- 新增 `remove` 命令
- token 自动续期（A1）
- use 前自动备份当前 Keychain (B1)

### config.json 帐号结构升级

```json
{
  "interval_minutes": 90,
  "ping_prompt": "hi",
  "accounts": [
    {
      "name": "primary",
      "credentials": {
        "accessToken":  "sk-ant-oat01-xxx",
        "refreshToken": "sk-ant-ort01-xxx",
        "expiresAt":    1779573809608,
        "scopes":       ["user:profile", "user:inference", ...],
        "subscriptionType": "pro",
        "rateLimitTier":    "default_claude_ai"
      },
      "offset_minutes": 0,
      "last_usage": {
        "five_hour":  {"utilization": 0.57, "resets_at": "2026-05-23T19:00:00Z"},
        "seven_day":  {"utilization": 0.14, "resets_at": "2026-05-28T15:00:00Z"},
        "fetched_at": "2026-05-23T14:30:00Z"
      }
    }
  ]
}
```

### v0.1 兼容性

v0.1 的 `token` 字段（长效 token）继续支持，但 `last_usage` 永远为 null（因为长效 token 查不到）。
迁移建议：用户运行 `interval-claude migrate` 时提示"请重新 add 该帐号以启用 usage 查询"。

不在本次实现自动迁移工具，让用户重新走一遍 add 流程即可。

## CLI 命令变更

### `add <name>` — 改造为 Keychain 捕获

```
$ interval-claude add primary
请先用 `claude /login` 登录该帐号，然后按回车继续...
[回车]
正在读取 Keychain 凭证...
✅ 已添加 primary
   订阅: Pro
   当前 5h 使用率: 57% (剩余 43%)
   5h 窗口重置: 2026-05-23 19:00 UTC
   7天周期使用率: 14%
```

实现：
1. 读 macOS Keychain `security find-generic-password -s "Claude Code-credentials" -w`
2. Parse JSON，取 `claudeAiOauth`
3. 立即调 `/api/oauth/usage` 拉一次（顺便验证 token 有效）
4. 写入 config

**批量模式（继承 v0.1 设计）：无参数时交互式批量**：
```
$ interval-claude add
准备好登录第 1 个帐号? [Y/n]: Y
请运行 `claude /logout && claude /login`，然后按回车...
[回车]
帐号名: primary
✅ 已添加 primary (Pro, 用了 57%)

准备好登录第 2 个帐号? [Y/n]: Y
...
```

**Linux 支持**（暂不实现，给 TODO）：
- Linux 上 claude CLI 把 credentials 存 `~/.config/claude/credentials.json`
- v0.2 仅 macOS（用 Keychain），其他平台报错"暂不支持"

### `use <name>` — 全局切换帐号 [新]

```
$ interval-claude use secondary
正在备份当前 Keychain 凭证...（找到归属帐号: primary）
正在写入 secondary 的凭证到 Keychain...
✅ 已切换到 secondary
   订阅: Pro
   当前 5h 使用率: 12% (剩余 88%)
所有终端的 `claude` 命令立即生效。
```

实现：
1. **备份当前**：读 Keychain → 与各帐号 config.credentials 比对 accessToken，找出归属
   - 找到归属（accessToken 完全匹配）→ 更新该帐号的 credentials（可能有 refresh 过的新 token）
   - 找不到归属 → 警告 "Keychain 中的 token 不属于任何已配置帐号，已忽略备份" 并继续
2. **写入目标**：把 `<name>` 的 credentials JSON 完整写回 Keychain
3. **刷新 usage**：调一次 usage API 验证 + 更新 last_usage

**边界处理**：
- Keychain 不存在（从未 /login）→ 跳过备份直接写入
- 目标 token 已过期 → 自动尝试 refresh，refresh 失败则报错"请重新 /login 该帐号并 add"

### `remove <name>` — 删除帐号 [新]

```
$ interval-claude remove tertiary
⚠️  确认删除帐号 tertiary? [y/N]: y
✅ 已删除
```

实现：
1. 询问确认
2. 从 config.accounts 移除
3. 如果当前 Keychain 是该帐号的，**不动 Keychain**（让 claude /login 还有效）

### `list` — 增强显示

```
NAME       SUB      5H USE  RESETS    7D USE  STATUS
-----------------------------------------------------------
primary    Pro       57%    in 4h32m   14%    🟢
secondary  Pro        0%    -           0%    ⚪ never pinged
tertiary   Max 5x    23%    in 2h11m    5%    🟢

interval_minutes=90  共 3 个帐号
```

**字段映射**：
- SUB: credentials.subscriptionType
- 5H USE: last_usage.five_hour.utilization * 100
- RESETS: 计算 last_usage.five_hour.resets_at - now
- 7D USE: last_usage.seven_day.utilization * 100
- STATUS: 🟢 < 80%, 🟡 80-95%, 🔴 ≥ 95%, ⚪ 从未 ping / 无数据

list 命令是否实时刷新 usage：
- **默认**：用 config 里缓存的 last_usage（避免每次 list 都调 API）
- **`--refresh`**：强制实时查询所有帐号

### `start` — 改为询问错峰

```
$ interval-claude start
检测到 3 个帐号: primary, secondary, tertiary
是否开启错峰激活? [Y/n]: Y
按 5h ÷ 3 = 100 分钟间隔错峰:
   primary    → 立即 ping
   secondary  → 100 分钟后 ping
   tertiary   → 200 分钟后 ping
✅ 守护进程已启动 (pid=12345)
日志: ~/.intervalClaude/daemon.log
```

去掉前一版 spec 提到的 `--stagger / --no-stagger / --no-prompt` 参数，简化为只有交互式询问。

无错峰时所有 offset=0，立即同时 ping。

### `ping <name>` — 使用 accessToken

继续用环境变量方式（`CLAUDE_CODE_OAUTH_TOKEN=<accessToken> claude -p hi`），不动 Keychain。
ping 成功后**顺便调一次 usage API** 更新 last_usage。

### `tui` — 实时多帐号仪表盘 [新]

```
$ interval-claude tui

┌─ intervalClaude · 守护进程运行中 (uptime 1h 23m) ───────────────────┐
│                                                                       │
│  NAME       SUB     5H USE        7D USE   NEXT PING    RESETS        │
│  ────────────────────────────────────────────────────────────────     │
│  primary    Pro    57% ███▌░░░    14%      ← 现在        in 4h 32m    │
│  secondary  Pro     0% ░░░░░░░     0%      in 1h 23m     -            │
│  tertiary   Max5x  23% █▌░░░░░     5%      in 3h 10m     in 2h 11m    │
│                                                                       │
│  当前 Keychain 活跃: primary                                          │
│                                                                       │
│  [r] 立即刷新 usage   [u] 切换帐号   [p] 手动 ping   [q] 退出         │
└───────────────────────────────────────────────────────────────────────┘
```

**实现**：
- 每 5 秒自动刷新（从 daemon state + last_usage 读，不实时调 API）
- 按 `r` 强制查 usage API 全部刷新
- 按 `u` 弹出帐号选择菜单 → 调用 use 命令
- 按 `p` 弹出帐号选择菜单 → 调用 ping 命令
- 按 `q` 干净退出（恢复光标、清屏）
- 守护进程未运行时 header 显示「守护进程未运行 — 按 s 启动」并增加 `[s]` 按键

**TUI 显示的字段**：
- **NAME**：帐号名
- **SUB**：订阅类型（Pro / Max 5x / Max 20x / Team）
- **5H USE**：进度条 + 百分比，颜色：< 70% 绿 / 70-90% 黄 / ≥ 90% 红
- **7D USE**：同上
- **NEXT PING**：距下次自动 ping 多久（"← 现在" / "in 1h 23m" / "—"）
- **RESETS**：5h 窗口距重置时间（"in 4h 32m"）

**底部状态栏**：
- 当前 Keychain 中活跃的帐号（通过 accessToken 比对）
- 错峰 interval 配置

`watch` 命令保留为简化版（无交互），`tui` 是完整交互版。
两者都基于 ANSI 转义，零依赖。

### `switch` 重命名为 `export-env`

避免和 `use` 混淆，旧 `switch` 改名 `export-env`：

```
$ eval "$(interval-claude export-env [name])"
# 只影响当前 shell 的环境变量
# vs use 命令影响所有终端
```

保留 `switch` 别名兼容 v0.1。

## Token 自动续期 (A1)

### 触发时机

1. **守护进程主循环**：每轮扫描时，对所有 token 检查 `expiresAt - now < 10 分钟` → 触发 refresh
2. **ping 前**：临时检查目标 token 是否过期，过期则先 refresh
3. **`use` 命令**：写 Keychain 前如果目标 token 过期，先 refresh

### Refresh endpoint

```
POST https://api.anthropic.com/api/oauth/token

Headers:
  Content-Type: application/json
  anthropic-beta: oauth-2025-04-20

Body:
{
  "grant_type": "refresh_token",
  "refresh_token": "sk-ant-ort01-xxx",
  "client_id": "9d1c250a-e61b-44d9-88ed-5944d1962f5e"   # claude CLI 的 client_id（需调研确认）
}

Response:
{
  "access_token": "sk-ant-oat01-yyy",
  "refresh_token": "sk-ant-ort01-zzz",   # 可能旋转，可能不变
  "expires_in": 28800,
  "token_type": "Bearer"
}
```

`client_id` 需要从 claude CLI 二进制或抓包获取，**这是 v0.2 实现的关键风险点**。如果拿不到正确的 client_id，refresh 会失败。

**降级方案**：refresh 失败时，提示用户手动 `claude /login` + `interval-claude add <name>` 重新捕获。

### 实现细节

新建 `src/oauth.js`：
- `refreshToken(credentials)` → 返回新 credentials
- `isExpiringSoon(credentials, thresholdMs=600000)` → boolean
- `queryUsage(accessToken)` → 调 usage API，包含 401 自动重试 (走一次 refresh 再试)

## 风险与开放问题

### Q1 — claude CLI 的 client_id 怎么拿？

**调研路径**：
1. `strings $(which claude) | grep -E 'client_id|9d1c'`
2. 抓包 `claude /login` 时浏览器跳转的 URL
3. 看 cc-switch 源码 (Rust) 是否硬编码

**预备方案**：如果拿不到，refresh 功能跳过，token 过期就让用户重新 add。

### Q2 — Keychain 跨平台

v0.2 仅 macOS。Linux/Windows 留 TODO。

### Q3 — 多帐号在不同电脑共享

如果用户在 Mac A 上添加帐号，配置文件可以拷到 Mac B 上用吗？
答：**可以**，但 B 上 `use` 时会覆盖 B 的 Keychain。需要在 README 提醒。

### Q4 — 并发 use

如果用户同时在两个终端跑 use，Keychain 会有竞争。
答：用 PID 锁文件 `~/.intervalClaude/.use.lock`，并发时后者等待或报错。本期不实现锁，提示"避免并发"。

## 验证计划

E2E 场景：
1. 给当前 Mac 上 3 个 claude 帐号都 `claude /login` + `interval-claude add`
2. 验证 3 个帐号都有 credentials 和 last_usage
3. `interval-claude list --refresh` 应显示三个真实 usage
4. `interval-claude use secondary` → 验证 Keychain 已切换（跑 `claude` 看是哪个帐号）
5. `interval-claude start` 选 Y → 验证错峰 offset 正确写入 + daemon 跑起来
6. 等几分钟，看 daemon.log 是否有 ping 记录 + usage 更新
7. 故意改一个帐号的 expiresAt 为 1（已过期）→ 触发 refresh → 验证 token 更新
